# Самостоятельное развёртывание Minder Publish

[English](SELF_HOSTING.md) · [Модель безопасности](SECURITY.md) · [API](implementation/API.md)

Minder Publish — отдельный сервис одного владельца для публикации файлов и готовых
статических сайтов. В нём есть личный кабинет, CLI и дополнительный MCP-адаптер.
Сервер работает через Docker Compose на
[поддерживаемых хостах](../README.md#supported-environments). Для его установки
и запуска Python на хосте не нужен.

## Что подготовить

- Docker с BuildKit и Compose на Linux (например, Ubuntu VPS) или OrbStack
  на macOS. Нужны постоянный диск и сетевой доступ для сборки релиза.
- Домен кабинета, например `publish.example.com`, и wildcard DNS
  `*.publish.example.com`, направленные на тот же reverse proxy. Для содержимого
  в первом релизе суффикс должен совпадать с доменом кабинета. Каждая неизменяемая
  версия получает свой поддомен. Встроенный просмотр остаётся на том же browser
  site, а origin публикаций изолированы. Отдельный cross-site-домен отклоняется.
- TLS-сертификат для домена кабинета **и** `*.CONTENT_DOMAIN`. Wildcard не покрывает
  вершину своего домена. Получение и продление выполняет выбранный вами провайдер
  через [DNS-01](https://letsencrypt.org/docs/challenge-types/#dns-01-challenge).
  DNS-учётные данные не передаются приложению.
- Место для материалов, временных загрузок, прошлых версий и резервных копий.
  Настроенный бюджет — ограничение допуска операций, а не измерение свободного диска.

В Compose заданы начальные ограничения: 1 GiB / 1 CPU для приложения, 128 MiB /
0,5 CPU для proxy, предел числа процессов и ротация Docker-логов. Это не гарантия
производительности. Оставьте ресурсы ОС, Docker и резервному копированию.
Значения приложения, максимумы и бюджеты обработчиков находятся в одном источнике:
[`defaults.json`](../src/minder_publish/defaults.json).

## Настройка и первый вход

Работайте из проверенного checkout выбранного релиза. Команды ниже собирают и
запускают контейнеры на вашем сервере; предварительно изучите Dockerfile и Compose.

```sh
cp .env.example .env
```

В `.env` укажите HTTPS-адрес кабинета, домен содержимого и дисковый бюджет. Используйте
обычные строки `NAME=value` с конкретными значениями. Используйте DNS-имя в ASCII
(Punycode для интернационализированного имени) без точки на конце. Конфигурация nginx
строится из выбранного файла окружения. `PUBLISH_DATA_DIR=/data` — путь
в контейнере; Compose подключает туда именованный том `publish-data`. Паролей и токенов
в этом файле быть не должно. Bootstrap создаёт `/data/server.secret` с закрытыми
правами. Вместо файла можно передать `PUBLISH_SECRET` из менеджера секретов: не менее
32 случайных байтов. Это секрет приложения.

```sh
docker compose build app &&
docker compose run --rm --no-deps -T --entrypoint python app \
  /opt/minder-publish/deploy/publish/render_config.py --env-file - --output - \
  < .env > deploy/publish/nginx.conf.tmp &&
mv deploy/publish/nginx.conf.tmp deploy/publish/nginx.conf &&
docker compose config --quiet &&
docker compose run --rm --no-deps app bootstrap --username owner
```

Bootstrap запросит пароль без отображения ввода. Для автоматизации используйте
`bootstrap --username owner --password-stdin`, передавая пароль через stdin из
менеджера секретов. Не помещайте пароль в аргументы команды или файлы репозитория.
Пароль владельца должен содержать не менее 12 UTF-8 байтов. Стандартного аккаунта и
публичной регистрации первого пользователя нет.

Compose задаёт `PUBLISH_TRUSTED_PROXIES=*` в отдельной сети приложения и proxy.
Наружу порты открывает только nginx. Оставляйте сокет приложения внутренним.

Каталог данных принадлежит UID/GID `10001:10001`, права — `0700`. Если вместо
именованного тома используется bind mount, сохраните эти права и владельца. Не
открывайте каталог всем пользователям для исправления ошибки доступа. Приложение
работает без root, с файловой системой образа только для чтения и небольшим tmpfs.

## TLS и запуск

Proxy читает `deploy/publish/tls/fullchain.pem` и `privkey.pem` только для чтения.
Выберите команды для своего хоста и замените исходные пути на файлы провайдера.
Каталог TLS и закрытый ключ должны иметь ограниченные права.

На Linux задайте владельца с UID/GID контейнера `101:101`:

```sh
sudo install -d -m 0750 -o 101 -g 101 deploy/publish/tls
sudo install -m 0400 -o 101 -g 101 /path/to/fullchain.pem deploy/publish/tls/fullchain.pem
sudo install -m 0400 -o 101 -g 101 /path/to/privkey.pem deploy/publish/tls/privkey.pem
```

На macOS с OrbStack положите файлы от имени текущего пользователя:

```sh
install -d -m 0700 deploy/publish/tls
install -m 0400 /path/to/fullchain.pem deploy/publish/tls/fullchain.pem
install -m 0400 /path/to/privkey.pem deploy/publish/tls/privkey.pem
```

На обоих хостах перед запуском проверьте конфигурацию и права TLS:

```sh
docker compose run --rm --no-deps proxy -t &&
docker compose up -d --wait &&
docker compose ps &&
docker compose exec app minder-publish-server doctor
```

`proxy -t` проверяет конфигурацию и сертификат без открытия публичных портов.
HTTP healthcheck сообщает состояние приложения. Политика `restart: unless-stopped`
перезапускает завершившийся процесс, но не контейнер только из-за статуса unhealthy.
Проверяйте также внешний HTTPS-адрес и свободное место на диске.

Опубликуйте небольшой личный файл, файл с паролем и ZIP сайта; откройте их владельцем
и в отдельном гостевом браузере. Проверьте ресурсы сайта, отсутствующий asset,
скачивание, Range, истечение срока и выход. До доступа посторонних должны пройти
браузерные проверки из [SECURITY.md](SECURITY.md#release-acceptance). Healthcheck
их не заменяет.

Продление сертификата должно обновлять смонтированные файлы с закрытыми правами,
запускать `docker compose exec proxy nginx -t`, затем
`docker compose exec proxy nginx -s reload`. Провайдер сертификатов, DNS-ключи и
служба продления не входят в приложение.

## Подключение AI-инструмента

Без сессии владельца `/` на домене кабинета показывает нейтральную страницу:
материал открывается по полученной ссылке, рядом есть вход для владельца. Списка
публикаций и регистрации на ней нет. Владелец входит на `/login`; после входа
открывается библиотека на `/`. С действующей сессией `/` сразу открывает кабинет.
Выход возвращает на нейтральную главную, истёкшая сессия — на `/login`. Английский,
русский, испанский и французский языки, а также тема используют общие host-only
cookies настроек. Правила доступа по ссылкам на материалы сохраняются.

Войдите на `/login`, откройте **Подключение** и выберите своё приложение. Для
Codex или Claude Code скопируйте одну инструкцию ассистенту: он установит клиент
с проверкой SHA-256 и компактный скилл вместе. Ассистент сообщит команду подключения
с полным путём к программе для вашего терминала — наличие программы в `PATH` не
требуется. Вставьте токен один раз в скрытый ввод этой команды; установка проверит
подключение. Секрет не попадает в чат. Ручная установка и восстановление скилла
доступны в дополнительном разделе.

Docker-образ содержит wheel с CLI и скиллом в `/opt/minder-publish/client.whl`.
Для установки из исходников выполните `python scripts/build-client-wheel.py` в
репозитории релиза и укажите абсолютный путь к wheel из `dist/client/` в
`PUBLISH_CLIENT_WHEEL`. Версия должна совпадать с сервером. В кабинете есть ссылки
и контрольные суммы установщика, wheel с CLI, полного ZIP скилла и пакета плагина.
Если wheel не задан, скачивание CLI недоступно.

Remote MCP по умолчанию выключен. Extra `mcp` уже есть в образе; при прямой установке
добавьте его отдельно. Задайте `PUBLISH_REMOTE_MCP=true` и перезапустите единственный
worker. Канонический endpoint/resource: `https://YOUR_CONTROL_HOST/mcp`. Proxy должен
сохранять Authorization и отключать буферизацию. Сервер провайдера должен иметь
сетевой доступ к HTTPS endpoint: доступ из браузера владельца этого не доказывает.

В ChatGPT выберите OAuth с автоматической регистрацией клиента (DCR), оставив
статические client ID и client secret пустыми. Инстанс предоставляет discovery
и поддерживает PKCE. Для Claude
также используйте OAuth и вариант **Register automatically** в выборе OAuth client.
Клиент с поддержкой фиксированных credentials может передавать свой токен устройства
в заголовке `Authorization: Bearer ...`; для этого варианта в Claude выберите **No sign in**.
Публикации нужен доступ `materials:manage`: чтение, создание, изменение и удаление
материалов. `materials:read` разрешает только чтение. Перед подтверждением согласия
проверьте запрошенные права. При подключении MCP сервис предлагает управление
материалами для публикации. Существующий доступ только на чтение не расширяется:
если приложение не запрашивает дополнительные права при вызове инструмента,
переподключите его и подтвердите управление перед публикацией.
Аккаунт, настройки и другие credentials этим grants недоступны. Приложения и токены
отзываются отдельно в блоке управления подключениями.

После подключения выберите, как приложение подтверждает вызовы инструментов:
спрашивать каждый раз или разрешить этому подключению работать без повторных запросов.
Автоматическое подтверждение позволяет изменять и удалять материалы в пределах
выданного доступа. В ChatGPT проверьте настройки разрешений приложения Publish или
окно подтверждения: варианты зависят от аккаунта, приложения и действия. В Claude
на сайте или компьютере откройте **Customize → Connectors → Publish → Permissions**
и проверьте каждый инструмент. **Always ask** внедряется постепенно и доступен не
всем; режим диалога также влияет на подтверждения. См. [инструкцию Claude](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork).
Эти подтверждения приложения не меняют OAuth-права, описанные выше. При помощи с
установкой ассистент один раз спрашивает предпочтение пользователя и применяет его
только через реально доступные настройки; если нужного варианта нет, сообщает об этом.
Скилл добавляет инструкции, но не выдаёт доступ и не меняет разрешения приложения.

Установите или включите созданное подключение и начните новый чат. В кабинете можно
скопировать запрос проверки: показать не более трёх материалов без каких-либо изменений.
Сначала проверьте его; скилл добавляет инструкции, но не обязателен для вызова MCP-инструментов.

В кабинете есть один ZIP скилла со всеми references для обоих приложений.
В ChatGPT откройте Plugins → Skills → Create → Upload from your computer; в Claude —
Customize → Skills → + → Create skill → Upload a skill. У части аккаунтов Claude раздел Skills
находится в Plugins или Customize. Загрузите ZIP и включите скилл с уже настроенным
MCP-подключением. Само скачивание ZIP не устанавливает скилл и не подключает аккаунт.
Используйте официальные инструкции
[подключения коннектора](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities)
и [загрузки скилла](https://support.claude.com/en/articles/12512180-use-skills-in-claude)
для доступного интерфейса. Доступность конкретного личного плагина на телефоне
проверяется на настоящем аккаунте. Отдельный plugin package доступен для приложений,
которые принимают такой формат; для прямой загрузки скилла он не нужен.

Текст UTF-8 и HTML до 1 MiB можно публиковать и обновлять напрямую.
Для PDF, изображений и ZIP сайта MCP-инструмент `create_file_upload` создаёт запрос:
владелец входит в браузере, выбирает файл, проверяет состав и подтверждает публикацию.
Этот сценарий создаёт новый материал. Для замены существующего бинарного файла или
сайта используйте управление материалом в кабинете или настроенный CLI.
`get_file_upload` возвращает подтверждённую ссылку. Удалённый MCP не читает пути сервера.
Опциональная передача файла провайдером включается через `PUBLISH_MCP_FILE_HOSTS` —
список точных доверенных HTTPS source hostnames через запятую. Оставьте его пустым,
пока настоящий источник файлов провайдера не проверен. Wildcard, произвольные URL
и следование redirect не разрешаются; загрузка проходит общие проверки и квоту.
Контракты находятся в [API](implementation/API.md) и [модели безопасности](SECURITY.md).

Не помещайте пароли и токены в skill, публикацию, аргумент команды, URL или контекст
модели. Для каждого устройства и приложения используйте отдельный отзывной доступ.
Подсказка к паролю материала видна до разблокировки: не указывайте в ней пароль и секреты.

## Сессии владельца

Учётку создаёт оператор локальной командой `bootstrap`. Email может быть именем
входа; SMTP и восстановление через email для этого не нужны. Восстановление доступа
делается локальной командой `reset-password`. Passkey в этот релиз не входит.

У сессии есть срок бездействия и абсолютный максимум после входа. Видимые действия
в кабинете продлевают её с заданным интервалом. Фоновая вкладка, проверка здоровья
и авторские страницы сессию не продлевают. Cookie и запись в БД обновляются вместе;
истёкшая сессия не восстанавливается. Создание подключения требует свежего подтверждения
пароля, сохраняя открытой текущую форму.

Оператор может переопределить соответствующие defaults из
[`defaults.json`](../src/minder_publish/defaults.json) переменными окружения:

| Переменная | Назначение |
| --- | --- |
| `PUBLISH_OWNER_SESSION_IDLE_DAYS` | Срок бездействия владельца |
| `PUBLISH_OWNER_SESSION_ABSOLUTE_DAYS` | Максимум после входа |
| `PUBLISH_OWNER_SESSION_REFRESH_SECONDS` | Минимальный интервал продления |
| `PUBLISH_OWNER_RECENT_AUTH_SECONDS` | Окно свежего подтверждения |

Значения — положительные целые числа с согласованными ограничениями. После изменения
перезапустите worker. Выход отзывает текущую browser session. Сброс пароля отзывает
сессии, токены устройств, OAuth grants и credentials доступа к контенту. Обычный выход
не отключает отдельно авторизованные приложения.

Перед проверкой и отправкой CLI создаёт закрытую временную копию передаваемых
байтов. На клиентском устройстве нужно дополнительное временное место до размера
выбранной загрузки и время на копирование или сборку ZIP. Изменение исходника после
подготовки не меняет байты, отправляемые этой операцией. Отдельная команда `preflight`
не сохраняет копию для последующего запуска `publish`. Передайте проверенный
`manifest_sha256` через `--expect-manifest HASH`, чтобы изменение содержимого
остановило публикацию до загрузки. Точный порядок подготовки и
очистки описан в [Client preparation](implementation/API.md#client-preparation).

## Просмотр владельца и открытия гостями

Обычная ссылка на материал для вошедшего владельца открывает тонкую панель над
документом. В меню доступны версии, копирование ссылки и пароля, скачивание и
счётчики гостевых открытий. Выбор прежней версии только показывает её; восстановление
создаёт новую текущую версию после подтверждения. «Без панели» открывает оригинал
отдельно, сохраняя вход владельца. Предпочтение показывать панель запоминается в
браузере. Проверка гостевого доступа использует реальные правила пароля и доступа
и не увеличивает счётчик. Гости не получают панель или статистику.

Счётчики означают принятые открытия ссылки, а не уникальных людей или дочитывания.
Подробности доступны за 7, 30 и 90 дней; границы дней обозначены UTC. Можно выключить
сбор у материала или очистить накопленные числа после повторного подтверждения входа.

## Сроки, место и обновления

Закрытие гостевого доступа, удаление файлов и хранение записи в библиотеке — отдельные
события. Срок закрывает доступ вовремя. В период восстановления файлы остаются в
пределах квоты, поэтому срок можно продлить. Файлы очищаются сразу, через период
восстановления или вручную — в рамках политики оператора. Срок записи отсчитывается
после фактического удаления файлов. Для восстановления удалённого содержимого нужна
новая загрузка и явный выбор срока доступа.

**Настройки** меняют значения новых публикаций и лимиты владельца в пределах максимумов
деплоя. **Лимиты загрузки** действуют в кабинете, при загрузке по запросу помощника,
через CLI и API. Новая установка допускает до 109 МиБ на обычный файл и до 109 МиБ
на передаваемый ZIP сайта. Настройки действующих инстансов сохраняются. В разделе
«Подключение» можно посмотреть текущие лимиты файлов и сайтов. В **Лимитах и хранилище** можно задать квоту места и предел числа
материалов, включая сохранённые записи без файлов. Снижение этих лимитов сохраняет
существующие материалы и их правила доступа и очистки. **История
версий** действует на весь инстанс: уменьшение количества, срока или доли места может
удалить прежние файлы при очистке; увеличение лимитов не возвращает удалённое.
Ноль в любом лимите истории отключает хранение прежних файлов. Текущие версии не
удаляются очисткой истории. История включена в общую квоту и показана в сводке места.
Подробности — [история версий](REVISION_HISTORY.md). Снижение общей квоты само по себе
не удаляет текущие файлы, но может остановить новые записи. У сайта есть предел передаваемого ZIP и
отдельные пределы размера после распаковки и числа файлов. Обычный ZIP остаётся
обычным файлом. Приложение не выполняет сборки и не скачивает произвольный исходный URL.

Задайте `PUBLISH_PROJECT_URL`, чтобы на гостевой главной, странице входа и
экране пароля появилась ссылка «Доступно через minder publish.». Если адрес
проекта не задан, эти страницы используют `PUBLISH_SOURCE_URL` для ссылки на
публичный репозиторий GitHub. Если оба адреса пусты, экран пароля ссылается
на главную инстанса. Используйте публичные HTTPS-адреса без учётных данных,
строки запроса и фрагмента. Сервер выводит ссылки без обращения к их адресам.

Оставьте один серверный worker. Неизменяемые версии, резервирование, проверка реального
диска, lease и фоновая очистка координируют работу с локальным томом. Старый sweeper
не должен обращаться к новому каталогу. Для ручного прохода очистки остановите запись:

```sh
docker compose stop app
docker compose run --rm --no-deps app sweep
docker compose start app
```

## Резервное копирование и восстановление

Храните резервные копии вне каталога данных, переносите их в отдельно защищённое
хранилище и шифруйте. В них есть личные файлы, метаданные, хэши учётных данных
и ключ шифрования паролей публикаций. Полная копия позволяет восстановить сохранённые
пароли публикаций.
TLS/DNS-учётные данные обслуживаются отдельно. Архив на том же диске не заменяет
внешнюю резервную копию.

Для согласованной копии остановите приложение и его фоновую работу. Proxy можно
оставить: пока приложение остановлено, запросы не выдадут содержимое. Подготовьте
закрытый каталог, доступный UID контейнера `10001`. На Linux выполните
`sudo install -d -m 0700 -o 10001 -g 10001 backups`. На macOS с OrbStack выполните
`install -d -m 0700 backups` от имени текущего пользователя.

```sh
docker compose stop app
docker compose run --rm --no-deps -v "$(pwd)/backups:/backup" app backup --output /backup/snapshot.tar
docker compose start app
```

Каждая копия должна иметь отдельное имя. Проверьте читаемость новой копии до удаления
старой. Репетируйте восстановление при остановленном приложении в пустой отдельный том:

```sh
docker volume create minder-publish-restore-check
docker compose run --rm --no-deps -v minder-publish-restore-check:/data -v "$(pwd)/backups:/backup:ro" app restore --input /backup/snapshot.tar
```

Восстановление отзывает восстановленные сессии, токены устройств, разрешения OAuth и
доступ к содержимому и записывает новый `server.secret`. Архивы версии 2 сохраняют
`publication-password.key`, чтобы пароли публикаций оставались доступны для копирования.
Сервер создаёт этот ключ в каталоге данных с правами `0600`. Храните ключ вместе
с зашифрованными записями. В архивах версии 1 остаются только хэши паролей. Эти пароли
работают после восстановления, а копировать их можно после повторного задания.
Для отката используйте совместимый образ и проверенную резервную копию.
Если менеджер секретов задаёт `PUBLISH_SECRET`, уберите override для использования
восстановленного `server.secret` либо укажите точное значение из этого файла.
Подключите доверенные инструменты заново. В старой копии могут быть материалы,
удалённые позже. Отдельно экспортируйте актуальный доступный реестр удалений:

```sh
docker compose run --rm --no-deps -v "$(pwd)/backups:/backup" app tombstones --output /backup/latest-tombstones.json
```

Каждый экспорт реестра должен иметь новое имя файла. Для переключения инстанса
зафиксируйте финальный реестр при остановленной записи. При восстановлении старой
копии передайте актуальный реестр:
`restore --input /backup/snapshot.tar --tombstones /backup/latest-tombstones.json`.
Храните и синхронизируйте реестр отдельно от старых архивов. Без более нового реестра
восстановление не может узнать об удалениях после момента копирования. Перед открытием
инстанса убедитесь, что удалённые ID недоступны. Истёкший срок не доказывает удаления.

После проверки количества записей, байтов, образцов файлов и состояния удалений
подключите восстановленный том через проверенный Compose override. Исходный том
сохраните для отката. Не используйте `docker compose down -v`: эта команда удаляет
именованный том с данными.

## Перенос из старого сервиса

Возьмите согласованную копию старой БД и файлов при остановленной записи. Смонтируйте
источник только для чтения и используйте отдельный новый том. Сначала:

```sh
docker compose run --rm --no-deps -v /path/to/legacy-copy:/legacy:ro app migrate --legacy-db /legacy/metadata.sqlite3 --legacy-blobs /legacy/blobs --dry-run
```

Проверьте отсутствующие файлы, конфликты ID, количество, размер и сроки. Затем
используйте ту же команду с `--apply`. Импорт сохраняет ID и смысл старого доступа;
сохранённые старые файлы получают политику без автоочистки до изменения владельцем.
Новый код и его sweeper не должны работать с исходным старым каталогом. Сохраните
резервную копию источника.

## Обновление и откат

Для обновления схемы и автономного отката используйте [порядок обновления и восстановления схемы](STATISTICS.md#schema-upgrade-and-recovery) и проверьте его на точной выбранной версии.

Проверьте релиз и его миграции, остановите запись, сделайте согласованную копию,
соберите зафиксированные зависимости и запустите версию на нужном томе. Выполните
`doctor`, проверьте публикацию, гостевой отказ после expiry и logout. Сохраните старый
образ и соответствующую ему копию данных. Запуск старого образа сам по себе не
откатывает схему БД: сначала восстановите совместимые данные в отдельный том.

Теги базовых образов обозначают релизы, но могут быть перевыпущены. Для публичного
образа необходимо зафиксировать digest, проверить уязвимости, сборку, восстановление
и браузерные ограничения по [критериям приёмки релиза](SECURITY.md#release-acceptance).

## Защита публичных ссылок

В настройках безопасности можно ограничить число открытий ссылки с одного IP за минуту (1–300, изначально 300). Для ввода пароля действуют отдельные настройки на каждый материал и IP — от 1 до 10 попыток за период от 15 до 60 минут. Изначально доступны 10 попыток за 15 минут. Период начинается при первой попытке. После исчерпания бюджета сервер возвращает HTTP 429 и число секунд до следующей попытки в заголовке `Retry-After`. Повторные запросы не продлевают блокировку. Новый лимит попыток действует сразу, новая длительность — со следующего периода. Защита входа владельца настроена отдельно.
